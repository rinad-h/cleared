# Migrations

SQL migrations for D1, generated by drizzle-kit from `src/db/schema.ts` and applied by Wrangler.

```bash
npm run db:generate                 # 1. after editing src/db/schema.ts
#                                     2. read the new SQL file; add what drizzle-kit can't (triggers)
npm run db:migrate                  # 3. apply to the local D1, run the tests (and `npm run preview`)
npm run db:migrate:remote           # 4. the deployment's D1, right before `npm run deploy`
```

Wrangler records applied files in the `d1_migrations` table and applies only new ones. It reads the `.sql` files; `meta/` is drizzle-kit's own state and must be committed too.

**From `0002_catalog.sql` on, migrations are additive only** (Phase 2, P2-31): the deployment holds the demo makerspace, so the first rule below is in force for every new file.

## Review checklist (every new migration)

Migrations run **before** the code that needs them is deployed, so the code that is still live must keep working against the new schema.

- [ ] **Additive only once the deployment has real data**: new tables, new columns, new indexes.
- [ ] **No `DROP` and no `RENAME`** of tables or columns. Stop using a column instead; never repurpose one.
- [ ] **New columns are nullable or have a `DEFAULT`.** `NOT NULL` without a default fails on existing rows.
- [ ] **Every hot filter is indexed** (pass page, status board, console polls). Each index adds a write per row change, so add only purposeful ones.
- [ ] **Triggers reviewed by hand.** drizzle-kit doesn't generate them (e.g. the append-only triggers on `service_records`); add them to the SQL file yourself.
- [ ] **`EXPLAIN QUERY PLAN`** run for every new hot query: no `SCAN` of a large table.
  ```bash
  npx wrangler d1 execute DB --local --command "EXPLAIN QUERY PLAN SELECT …"
  ```
- [ ] **Fully qualified names in correlated subqueries** inside Drizzle `sql` templates (`"machine_requirements"."machine_id" = "machines"."id"`); Drizzle drops table names in single-table queries.
- [ ] **Conventions** (docs/phases/README.md §4.1): `TEXT` uuid primary keys; `INTEGER` Unix-ms UTC `*_at`; booleans `INTEGER` 0/1 with `CHECK`; enums `TEXT` + `CHECK`; foreign keys `ON DELETE RESTRICT`.
- [ ] Applied locally with tests green (there is no staging copy), then to the deployment. **Never roll back a migration; write a new one.** If one breaks the live database, restore with D1 Time Travel (`docs/runbook.md`).
